推出 MCP 注册表

发布日期：2025 年 9 月 8 日　阅读时长：约 4 分钟

作者：David Soria Parra（首席维护者）、Adam Jones（注册表维护者）、Tadas Antanavicius（注册表维护者）、Toby Padilla（注册表维护者）、Theodora Chu（Anthropic 的 MCP 产品经理）

今天，我们正式推出模型上下文协议（MCP）注册表的预览版——这是一个面向公开可用 MCP 服务器的开放目录与 API，用于改善其可发现性与落地实现。通过标准化服务器分发与发现的方式，我们正在扩展服务器的覆盖范围，同时让客户端更容易接入。

MCP 注册表现在已开放预览。要开始使用，请：

  • 如果你是服务器维护者，请遵循我们的指南 向 MCP 注册表添加服务器（Adding Servers to the MCP Registry）
  • 如果你是客户端维护者，请遵循我们的指南 访问 MCP 注册表数据（Accessing MCP Registry Data）

MCP 服务器的单一可信来源

2025 年 3 月，我们曾表示希望为 MCP 生态构建一个中央注册表。今天，我们宣布已上线 https://registry.modelcontextprotocol.io，作为官方的 MCP 注册表。作为 MCP 项目的一部分，MCP 注册表以及一个父级的 OpenAPI 规范都是开源的——这允许任何人构建兼容的子注册表。

我们的目标是标准化服务器的分发与发现方式，提供一个可供子注册表在其之上构建的主要可信来源。由此，这将扩展服务器的覆盖范围，并帮助客户端在 MCP 生态中更轻松地找到服务器。

公共与私有子注册表

在构建中央注册表时，我们十分重视一点：不去削弱社区和企业已经建好的现有注册表。MCP 注册表作为公开可用 MCP 服务器的主要可信来源，而各组织可以选择基于自定义标准来创建子注册表。例如：

  • 公共子注册表：与各个 MCP 客户端相关联、带有主观倾向性的"MCP 市场（MCP marketplaces）"是自由的，它们可以对从上游 MCP 注册表摄取的数据进行扩充与增强。每个 MCP 终端用户的画像都有不同需求，如何以主观倾向性的方式妥善服务其终端用户，取决于这些 MCP 客户端市场。
  • 私有子注册表：将存在于那些有着严格隐私与安全要求的企业内部，但 MCP 注册表为这些企业提供了一个可供其构建的单一上游数据源。至少，我们旨在与这些私有实现共享 API 模式（API schemas），以便相关的 SDK 与工具能够在整个生态中复用。

在这两种情况下，MCP 注册表都是起点——它是 MCP 服务器维护者发布并维护其自行上报信息的地方，这些信息再由下游消费者加工、交付给他们的终端用户。

社区驱动的审核机制

MCP 注册表是由注册表工作组维护的官方 MCP 项目，并采用宽松许可证。社区成员可以提交 issue，以标记那些违反 MCP 审核指南（moderation guidelines）的服务器——例如包含垃圾信息、恶意代码，或冒充合法服务的服务器。注册表维护者随后可以将这些条目加入拒绝列表（denylist），并事后将其从公开访问中移除。

快速开始

要开始使用，请：

  • 如果你是服务器维护者，请遵循我们的指南 向 MCP 注册表添加服务器（Adding Servers to the MCP Registry）
  • 如果你是客户端维护者，请遵循我们的指南 访问 MCP 注册表数据（Accessing MCP Registry Data）

此次 MCP 注册表的预览版，旨在帮助我们在正式发布（general availability）之前改善用户体验，并不提供数据持久性保证或其他任何担保。我们建议 MCP 的采用者密切关注其开发进展，因为在注册表正式发布之前，可能会出现破坏性变更（breaking changes）。

随着我们持续开发该注册表，我们鼓励大家在 modelcontextprotocol/registry GitHub 仓库中提供反馈与贡献：欢迎展开讨论（Discussion）、提交 Issue 与拉取请求（Pull Request）。

致谢 MCP 社区

MCP 注册表从一开始就是一项协作努力的成果，我们对广大开发者社区的热情与支持深表感激。2025 年 2 月，当 MCP 的创造者 David Soria Parra 和 Justin Spahr-Summers 邀请 PulseMCP 与 Goose 团队协助构建一个集中的社区注册表时，它作为一项草根项目起步。来自 PulseMCP 的注册表维护者 Tadas Antanavicius 在与 Block 的 Alex Hancock 协作下，牵头了最初的这项工作。很快，GitHub 的 MCP 负责人、注册表维护者 Toby Padilla 也加入了他们；更近一些时候，来自 Anthropic 的 Adam Jones 也以注册表维护者的身份加入，推动项目走到今天的发布。MCP 注册表开发的最初公告中，列出了来自至少 9 家不同公司的 16 位贡献者。

还有许多其他人做出了关键贡献，让这个项目得以成真：来自 Stacklok 的 Radoslav Dimitrov、来自 GitHub 的 Avinash Sridhar、来自 VS Code 的 Connor Peet、来自 NuGet 的 Joel Verhagen、来自 Last9 的 Preeti Dewani、来自 Microsoft 的 Avish Porwal、Jonathan Hefner，以及众多为项目提供了代码审查与开发支持的 Anthropic 与 GitHub 员工。我们也感谢注册表贡献者日志（contributors log）上的所有人，以及那些参与讨论与 Issue 的人。我们深深感激每一位为这一基础开源基础设施投入心血的人。携手同行，我们正在帮助全球的开发者与组织构建更可靠、更具上下文感知能力的 AI 应用。谨代表 MCP 社区，向大家致谢。
