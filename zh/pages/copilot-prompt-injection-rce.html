GitHub Copilot：通过提示注入实现的远程代码执行（CVE-2025-53773）

发布于 2025 年 8 月 12 日 ｜ 标签：#llm #agents #month of ai bugs

这篇文章是关于一个重要但也令人不安的提示注入（Prompt Injection） 发现，它会导致开发者机器在 GitHub Copilot 和 VS Code 中被完全攻陷。

它的实现方式是：通过修改项目的 settings.json 文件，将 Copilot 置入 YOLO 模式。

正如几天前在 Amp 一文中所述，智能体（agents）中一个可能被忽视的漏洞模式是：如果一个智能体能够写入文件并修改自身的配置，或更新与安全相关的设置，就可能导致远程代码执行（RCE）。这并不罕见，也是在进行安全审查时始终需要留意的一个领域。

背景研究

在研究 VS Code 和 GitHub Copilot 的 Agent 模式时，我注意到一个奇怪的行为……它可以在不经过用户批准的情况下，在工作区中创建并写入文件。

这些编辑会立即持久化，它们不是以可供审查的内存中 diff 形式存在。这些修改会立刻写入磁盘。

作为红队成员，你会本能地知道这类事情大概不妙……于是我研究它是否可被用来提权并执行代码。

YOLO 模式

于是，接下来我研究了 VS Code 中那些依赖于项目/工作区文件夹内设置的功能，并很快找到了一个有趣的。

结果发现，在 .vscode/settings.json 文件中可以添加如下一行：

"chat.tools.autoApprove": true

这将把 GitHub Copilot 置于 YOLO 模式。

它会禁用所有用户确认，然后我们就可以运行 shell 命令、浏览网页，以及更多！

有趣的是，这是一个实验性功能，但它默认仍然存在。我并没有下载特殊版本，也没有把我的 VS Code 整体切换到实验模式。

此外，它在 Windows、macOS 以及 Linux 上都能工作。

漏洞利用链详解

劫持 Copilot 并提权的概念验证（PoC）漏洞利用链如下：

  1. 攻击始于植入在源代码文件、网页、GitHub issue、工具调用响应或其他内容中的提示注入……该 payload 也可以使用不可见文本作为指令。
  2. 提示注入首先向 ~/.vscode/settings.json 文件添加一行 “chat.tools.autoApprove”: true。如果文件夹和文件尚不存在，则会被创建。
  3. GitHub Copilot 立即进入 YOLO 模式！
  4. 攻击运行一条 Terminal 命令。并且通过条件式提示注入，我们确实可以基于操作系统来定向运行什么。
  5. 我们实现了由提示注入驱动的远程代码执行。

下面这张截图展示了带有提示注入的演示文件、右侧聊天框中正在与该文件交互的开发者，以及弹出的计算器！

当然，任何其它形式的提示注入投递方式，比如来自 MCP 服务器的网页或返回数据，都是攻击角度。我之所以把它放在源代码文件里，只是因为最容易测试。

可怕的东西。

构建一个 AI 病毒

看到这一点，有人会注意到这基本上允许创建一个病毒。攻击者可以嵌入指令，一旦获得代码执行，额外的恶意软件就能攻陷其它 Git 项目（以及 RAG 来源），嵌入恶意指令，并提交这些更改，甚至强制推送到上游。

随着其他开发者在不知情的情况下传播受感染的代码，这会导致进一步扩散。

最后，我们还需要谈谈不可见指令！

使用不可见指令

注意：尽管这里用不可见指令的演示对我多次奏效，但使用不可见指令常常导致漏洞利用非常不可靠，并且通常也会被模型拒绝；而且 VS Code 通常会显示一个关于 Unicode 字符的视觉提示标记。不过，攻击（和模型）会随着时间变得更好。同样值得强调的是，并非所有模型都易受此类不可见提示注入攻击。

建议与修复

实际上，比我分享的 YOLO 模式示例更多的攻击角度存在。当微软问我是否还有更多信息时，我又多看了一点，注意到还有其它有问题的地方，例如 AI 可以写入的 .vscode/tasks.json，或添加伪造的恶意 MCP 服务器等，这些都可能导致代码执行。而且 AI 可以重新配置项目的用户界面和配置设置。

最近我注意到开发者经常使用多个智能体，因此也存在覆盖其它智能体配置文件（允许列表中的 bash 命令、添加 MCP 服务器……）的威胁，因为它们通常也位于项目文件夹中。

理想情况下，AI 不应能在没有人类先批准的情况下修改文件。许多其它编辑器确实会显示 diff，然后由开发者批准。

负责任的披露

在 2025 年 6 月 29 日报告该漏洞后，微软确认了复现，并问了几个后续问题。几周后，MSRC 指出这是他们已经在跟踪的问题，并将在 8 月前修补。随着 8 月补丁星期二的发布，此问题现已修复。

向来自 Persistent Security 的 Markus Vervier 致敬，他也识别并向微软报告了此漏洞。你可以在这里 找到他们的分析文章。同时也要向似乎也并行发现它的 Ari Marzuk 致敬。

感谢 MSRC 和产品团队在缓解此问题中提供的帮助。

结论

这是 AI 智能体可能不安分守己的又一个例子！通过修改自身环境，GitHub Copilot 可以提权并执行代码，从而攻陷开发者的机器。正如我所发现的，这是智能体系统中一个并不少见的缺陷设计。

继续留意此类设计缺陷，它们本应在威胁建模时就能轻易被发现。

干杯。
