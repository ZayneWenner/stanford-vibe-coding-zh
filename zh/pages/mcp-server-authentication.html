构建远程 MCP 服务器

本指南将介绍如何使用 Streamable HTTP 传输（当前 MCP 规范标准）在 Cloudflare 上部署你自己的远程 MCP 服务器。你有两种选择：

  • 无需认证——任何人都可连接并使用该服务器（无需登录）。
  • 带认证与授权——用户在访问工具前需先登录，并且你可以基于用户权限控制某个智能体可以调用哪些工具。

选择方案

Agents SDK 提供了多种创建 MCP 服务器的方式。请根据你的使用场景选择合适的方案：

方案有状态？需要 Durable Objects？最适合
createMcpHandler()否否无状态工具，最简单的配置
McpAgent是是有状态工具、按会话保存状态、支持 elicitation（询问）
原生 WebStandardStreamableHTTPServerTransport否否完全掌控，不依赖 SDK
  • createMcpHandler() 是启动一个无状态 MCP 服务器最快的方式。当你的工具不需要按会话保存状态时使用它。
  • McpAgent 为每个会话提供一个 Durable Object，内置状态管理、elicitation 支持，并同时支持 SSE 与 Streamable HTTP 两种传输方式。
  • 原生传输方式让你在使用 @modelcontextprotocol/sdk 时拥有完全掌控，且不依赖 Agents SDK 的辅助函数。

部署你的第一个 MCP 服务器

你可以先部署一个无需认证的公开 MCP 服务器，之后再补上用户认证与范围化授权。如果你已经确定服务器需要认证，可以直接跳到下一节。

通过控制台（Dashboard）

下方按钮会引导你完成将示例 MCP 服务器部署到你的 Cloudflare 账户所需的一切操作。

部署完成后，该服务器将运行在你的 workers.dev 子域名下（例如 remote-mcp-server-authless.your-account.workers.dev/mcp）。你可以立即通过 AI Playground（一个远程 MCP 客户端）、MCP Inspector 或其他 MCP 客户端连接它。

系统会在你的 GitHub 或 GitLab 账户上为你这个 MCP 服务器建立一个全新的 git 仓库，并配置为：每当你向仓库的 main 分支推送改动或合并拉取请求时，自动部署到 Cloudflare。你可以克隆该仓库、在本地开发，并开始用你自己的工具定制这个 MCP 服务器。

通过 CLI

你可以使用 Wrangler CLI 在本地机器上创建新的 MCP 服务器并部署到 Cloudflare。

  • 打开终端并运行以下命令：

使用 npm：

npm create cloudflare@latest -- remote-mcp-server-authless --template=cloudflare/ai/demos/remote-mcp-authless

使用 yarn：

yarn create cloudflare remote-mcp-server-authless --template=cloudflare/ai/demos/remote-mcp-authless

使用 pnpm：

pnpm create cloudflare@latest remote-mcp-server-authless --template=cloudflare/ai/demos/remote-mcp-authless

在设置过程中，请选择以下选项：

  • 对于"是否要添加 AGENTS.md 文件以帮助 AI 编码工具理解 Cloudflare API？"，选择 No。
  • 对于"是否要使用 git 进行版本控制？"，选择 No。
  • 对于"是否要部署你的应用？"，选择 No（我们会在部署前先测试服务器）。

现在，你的 MCP 服务器已经配置完成，依赖也已安装。

  • 进入项目文件夹：
cd remote-mcp-server-authless
  • 在新项目目录下，运行以下命令启动开发服务器：
npm start
⎈ Starting local server...[wrangler:info] Ready on http://localhost:8788

请查看命令输出中的本地端口。在此示例中，MCP 服务器运行在端口 8788，MCP 端点 URL 为 http://localhost:8788/mcp。

注意：你无法通过直接在 Web 浏览器中打开 /mcp URL 来与 MCP 服务器交互。/mcp 端点期望由 MCP 客户端发送 MCP 协议消息，而浏览器默认不会这样做。下一步我们将演示如何使用 MCP 客户端连接服务器。

  • 要在本地测试服务器：

在一个新的终端里，运行 MCP Inspector。MCP Inspector 是一个交互式 MCP 客户端，允许你从 Web 浏览器连接 MCP 服务器并调用工具。

npx @modelcontextprotocol/inspector@latest
🚀 MCP Inspector is up and running at: http://localhost:5173/?MCP_PROXY_AUTH_TOKEN=46ab..cd3
🌐 Opening browser...

MCP Inspector 将在你的 Web 浏览器中启动。你也可以手动启动它：打开浏览器并访问 http://localhost:<PORT>。请查看命令输出，确认 MCP Inspector 运行的本地端口。在此示例中，MCP Inspector 运行在端口 5173。

  • 在 MCP Inspector 中，输入你的 MCP 服务器 URL（http://localhost:8788/mcp），然后选择 Connect（连接）。选择 List Tools（列出工具）以显示 MCP 服务器暴露的工具。
  • 你现在可以将 MCP 服务器部署到 Cloudflare。从你的项目目录运行：
npx wrangler@latest deploy

如果你已经为承载 MCP 服务器的 Worker 连接了 git 仓库，你也可以通过向仓库 main 分支推送改动或合并拉取请求来部署 MCP 服务器。

MCP 服务器将被部署到你的 *.workers.dev 子域名，地址为 https://remote-mcp-server-authless.your-account.workers.dev/mcp。

  • 要测试远程 MCP 服务器，请取你已部署 MCP 服务器的 URL（https://remote-mcp-server-authless.your-account.workers.dev/mcp），并输入到运行在 http://localhost:5173 的 MCP Inspector 中。

现在你拥有了一个 MCP 客户端可以连接的远程 MCP 服务器。

通过本地代理从 MCP 客户端连接

既然你的远程 MCP 服务器已经在运行，你可以使用 mcp-remote 本地代理 将 Claude Desktop 或其他 MCP 客户端连接到它——即使你的 MCP 客户端不支持远程传输或服务端授权也没关系。这可以让你用一个真实的 MCP 客户端测试与远程 MCP 服务器的交互体验。

例如，要从 Claude Desktop 连接：

  • 更新你的 Claude Desktop 配置，使其指向你的 MCP 服务器 URL：
{
  "mcpServers": {
    "math": {
      "command": "npx",
      "args": [
        "mcp-remote",
        "https://remote-mcp-server-authless.your-account.workers.dev/mcp"
      ]
    }
  }
}
  • 重启 Claude Desktop 以加载该 MCP 服务器。完成后，Claude 就能调用你的远程 MCP 服务器了。
  • 要测试，可以让 Claude 使用你的某个工具。例如：
你能用 math 工具把 23 和 19 加起来吗？

Claude 应当会调用该工具，并展示由远程 MCP 服务器生成的结果。

要了解如何与其他 MCP 客户端一起使用远程 MCP 服务器，请参阅 测试远程 MCP 服务器。

添加认证

你之前部署的公开 MCP 服务器示例允许任何客户端在无需登录的情况下连接并调用工具。要给你的 MCP 服务器添加用户认证，你可以将 Cloudflare Access 或第三方服务集成为 OAuth 提供方。你的 MCP 服务器负责处理安全的登录流程，并签发访问令牌（access token），供 MCP 客户端用于发起经过认证的 tool 调用。用户通过 OAuth 提供方登录，并授予其 AI 智能体使用范围化（scoped）权限来与你的 MCP 服务器暴露的工具交互。

Cloudflare Access OAuth

你可以将 MCP 服务器配置为要求用户通过 Cloudflare Access 进行认证。Cloudflare Access 充当身份聚合器，验证用户邮箱、来自你现有身份提供方（如 GitHub 或 Google）的信号，以及其他属性（如 IP 地址或设备证书）。当用户连接 MCP 服务器时，会被提示登录已配置的身份提供方，只有在通过你的Access 策略后才会被授予访问权限。

关于分步部署指南，请参阅 使用 Access for SaaS 保护 MCP 服务器。

第三方 OAuth

你可以将 MCP 服务器与任何支持 OAuth 2.0 规范的 OAuth 提供方连接，包括 GitHub、Google、Slack、Stytch、Auth0、WorkOS 等。

以下示例演示如何使用 GitHub 作为 OAuth 提供方。

第 1 步 —— 创建新的 MCP 服务器

运行以下命令，创建一个带 GitHub OAuth 的新 MCP 服务器：

使用 npm：

npm create cloudflare@latest -- my-mcp-server-github-auth --template=cloudflare/ai/demos/remote-mcp-github-oauth

使用 yarn：

yarn create cloudflare my-mcp-server-github-auth --template=cloudflare/ai/demos/remote-mcp-github-oauth

使用 pnpm：

pnpm create cloudflare@latest my-mcp-server-github-auth --template=cloudflare/ai/demos/remote-mcp-github-oauth

现在，你的 MCP 服务器已经配置完成，依赖也已安装。进入该项目文件夹：

cd my-mcp-server-github-auth

你会注意到，在示例 MCP 服务器中，如果你打开 src/index.ts，主要的区别在于 defaultHandler 被设置成了 GitHubHandler：

import GitHubHandler from "./github-handler";

export default new OAuthProvider({
  apiRoute: "/mcp",
  apiHandler: MyMCP.serve("/mcp"),
  defaultHandler: GitHubHandler,
  authorizeEndpoint: "/authorize",
  tokenEndpoint: "/token",
  clientRegistrationEndpoint: "/register",
});

这确保用户会被重定向到 GitHub 进行认证。不过要让它工作，你需要在下面的步骤中创建 OAuth 客户端应用。

第 2 步 —— 创建 OAuth 应用

你需要创建两个 GitHub OAuth App，将 GitHub 用作 MCP 服务器的认证提供方——一个用于本地开发，一个用于生产环境。

第 2.1 步 —— 为本地开发创建新的 OAuth 应用

  • 前往 github.com/settings/developers 创建一个新的 OAuth App，设置如下：
    • Application name（应用名称）：My MCP Server (local)
    • Homepage URL（主页 URL）：http://localhost:8788
    • Authorization callback URL（授权回调 URL）：http://localhost:8788/callback
  • 对于你刚创建的 OAuth App，将它的 client ID 添加为 GITHUB_CLIENT_ID，并生成一个 client secret 添加为 GITHUB_CLIENT_SECRET，写入项目根目录的 .env 文件中，该文件将用于在本地开发中设置密钥：
touch .env
echo 'GITHUB_CLIENT_ID="your-client-id"' >> .env
echo 'GITHUB_CLIENT_SECRET="your-client-secret"' >> .env
cat .env
  • 运行以下命令启动开发服务器：
npm start

你的 MCP 服务器现在运行在 http://localhost:8788/mcp。

  • 在一个新的终端里，运行 MCP Inspector。MCP Inspector 是一个交互式 MCP 客户端，允许你从 Web 浏览器连接 MCP 服务器并调用工具。
npx @modelcontextprotocol/inspector@latest
  • 在你的 Web 浏览器中打开 MCP Inspector：
open http://localhost:5173
  • 在 Inspector 中，输入你的 MCP 服务器 URL：http://localhost:8788/mcp。
  • 在右侧主面板中，点击 OAuth Settings（OAuth 设置）按钮，然后点击 Quick OAuth Flow（快速 OAuth 流程）。

你应该会被重定向到 GitHub 登录或授权页面。在授权 MCP 客户端（即 Inspector）访问你的 GitHub 账户后，你会被重定向回 Inspector。

  • 在侧边栏点击 Connect（连接），你应该会看到"List Tools"（列出工具）按钮，点击它会列出你的 MCP 服务器暴露的工具。

第 2.2 步 —— 为生产环境创建新的 OAuth 应用

你需要重复第 2.1 步，为生产环境创建一个新的 OAuth App。

  • 前往 github.com/settings/developers 创建一个新 OAuth App，设置如下：
    • Application name（应用名称）：My MCP Server (production)
    • Homepage URL（主页 URL）：填入你已部署 MCP 服务器的 workers.dev URL（例如 worker-name.account-name.workers.dev）
    • Authorization callback URL（授权回调 URL）：填入你已部署 MCP 服务器的 workers.dev URL 的 /callback 路径（例如 worker-name.account-name.workers.dev/callback）
  • 对于你刚创建的 OAuth App，使用 Wrangler CLI 添加 client ID 与 client secret：
npx wrangler secret put GITHUB_CLIENT_ID
npx wrangler secret put GITHUB_CLIENT_SECRET
npx wrangler secret put COOKIE_ENCRYPTION_KEY # 这里填入任意随机字符串，例如：openssl rand -hex 32

警告：当你创建第一个 secret 时，Wrangler 会询问是否要创建一个新的 Worker。请输入 "Y" 以创建新 Worker 并保存该 secret。

  • 设置一个 KV 命名空间：

a. 创建 KV 命名空间：

npx wrangler kv namespace create "OAUTH_KV"

b. 用得到的 KV ID 更新 wrangler.jsonc 文件：

{
  "kvNamespaces": [
    {
      "binding": "OAUTH_KV",
      "id": "<YOUR_KV_NAMESPACE_ID>"
    }
  ]
}
  • 将 MCP 服务器部署到你的 Cloudflare workers.dev 域名：
npm run deploy
  • 使用 AI Playground、MCP Inspector 或其他 MCP 客户端，连接到运行在 worker-name.account-name.workers.dev/mcp 的服务器，并用 GitHub 进行认证。
